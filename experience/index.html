Featured work

RabbitMQ & Inventory backlog

Problem

Shoppers browsing a mall's products rely on the "In Stock" badge being real-time and accurate. Behind it, stock updates waited in a message queue that was falling behind: messages arrived faster than they were processed, old messages never expired, and the backlog kept growing. In-stock badges went stale, which lowered shopper trust.

What I did

I traced the backlog to several causes and fixed each one. I switched the service to push-based delivery, so it receives work as soon as it arrives instead of repeatedly asking for it, and limited how many messages are processed at once. I made sure every store's queue always has a consumer, added message expiry so stale messages are dropped, and cached a repeated status check to save resources.

Result

Processing is now many times faster, the backlog drains instead of growing, and inventory updates stay close to real time.
