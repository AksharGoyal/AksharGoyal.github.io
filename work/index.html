RabbitMQ & Inventory backlog

Problem

Shoppers browsing a mall's products rely on the "In Stock" badge being real-time and accurate. Behind it, stock updates waited in a message queue that was falling behind: it processed about 0.2 messages a second, old messages never expired, and the backlog grew every week. In-stock badges went stale, which lowered shopper trust.

What I did

I traced the backlog to several causes and fixed each one. I switched the service to push-based delivery, so it receives work as soon as it arrives instead of repeatedly asking for it, and limited how many messages are processed at once. I made sure every store's queue always has a consumer, added message expiry so stale messages are dropped, and cached a repeated status check to save resources.

Result

Healthy queues now process at least 5 messages a second, about 25 times faster. The backlog dropped from weeks to days, and inventory updates now stay close to real time.
